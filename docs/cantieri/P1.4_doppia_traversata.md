# P1.4 — Eliminazione della doppia traversata del ramo in App

## Descrizione sintetica del fix

In `App` il ramo veniva percorso due volte per ogni proprietà:

- `App:164` / `App:270` chiamavano `TopologicalVectorUpdater.recoverBranch(...)` solo come gate booleano (`!= null`);
- subito dopo, `recoverTriples(memory, entityUri, predicateUri)` a 3 argomenti ricalcolava internamente `recoverBranch(...)`.

Fix applicato, a comportamento osservabile invariato:

1. Aggiunto in `TopologicalVectorUpdater` un overload **non sostitutivo**:
   ```java
   public List<HDVector> recoverTriples(
           ItemMemory memory, String entityUri, String predicateUri, HDVector precomputedBranch)
   ```
   Comportamento: identico a `recoverTriples/3` ma salta `recoverBranch` e usa `precomputedBranch`.
   Ritorna `List.of()` se `tree == null` oppure se `precomputedBranch == null`.
   Il metodo a 3 argomenti resta invariato.

2. In `App:169` e `App:291` la chiamata passa ora il ramo già calcolato (`cleanBranch`, `pureTargetBranch`).

Non sono stati toccati: logica z-score, log di confidenza, `getLastStructuralSigma()`.
